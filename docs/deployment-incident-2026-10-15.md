# 배포 안정화 기록 (2026-10-15)

## 문제 상황

- 운영 주소 `https://ppodeuk-user.vercel.app/`에서 로그인은 가능했지만 추천 세차장과 예약 화면이 로딩 후 실패했다.
- 데스크톱 화면은 렌더링됐으나 콘텐츠 폭이 과도하게 늘어났고, 핵심 예약 흐름을 끝까지 시연할 수 없었다.

## 원인 찾기

1. 브라우저 콘솔에서 Axios `timeout: 5000` 오류를 확인했다.
2. 운영 API `https://ppodeuk-backend.up.railway.app`를 직접 호출해 프런트와 서버를 분리 진단했다.
3. 사용자 로그인은 성공했지만 첫 응답에 약 11.1초가 걸렸다. 이는 프런트 제한 5초보다 길었다.
4. 서버가 깨어난 뒤에도 추천, 주변 세차장, 현재 예약 API가 HTTP 500을 반환했다.

## 판단 및 해결 방법

- 제한 시간만 늘리면 사용자가 더 오래 기다린 뒤 같은 500 오류를 보게 되므로 근본 해결이 아니다.
- 회사 제출용 공개 주소는 백엔드 상태와 무관하게 재현 가능해야 한다.
- 이미 구축하고 101개 테스트로 검증한 MSW 데모 API를 Vercel 기본 배포에 연결했다.
- `vercel.json`에서 `npm run build:demo`와 `dist-demo`를 명시해 배포 환경 차이로 실 API 빌드가 나가는 것을 방지했다.

## 결과

- 로그인, 추천/주변 세차장, 상세 조회, 예약 선택, 데모 결제, 예약 내역과 취소가 브라우저 내부의 결정적 데이터로 동작한다.
- 실제 운영 API 장애나 콜드 스타트가 포트폴리오 시연을 막지 않는다.
- 실 API 연동 빌드는 기존 `npm run build`로 분리 유지한다.

## 검증과 성과

- 단위·통합 테스트: 25개 파일, 101개 테스트 통과
- ESLint: 경고 0개
- 데모 프로덕션 빌드: 성공
- 배포 후 남은 확인: Vercel 빌드 명령 적용 여부와 실제 모바일 클릭 흐름 재검증

## 후속 개선

- 실 서비스 전환 전 Railway 로그와 데이터베이스 마이그레이션/시드 상태를 확인해 HTTP 500을 별도 복구한다.
- 백엔드 콜드 스타트 대응은 헬스 체크 또는 항상 실행되는 인스턴스로 해결하고, 프런트 제한 시간은 사용자 피드백과 함께 재설계한다.

## 추가 사례: 비로그인 홈 추천 누락

### 문제 상황

- 로그인 후에는 추천 세차장 이미지가 표시됐지만 비로그인 첫 화면에서는 추천 결과가 표시되지 않는 경우가 있었다.

### 원인

- 추천 API는 공개 API라 인증 자체가 원인은 아니었다.
- 추천 요청에 좌표가 필요하지만 위치 권한 거부·미지원·타임아웃을 명시적으로 처리하지 않았다.
- 추천 API 실패 또는 빈 응답 시 오류 문구만 표시하고 대체 콘텐츠가 없었다.

### 해결 방법

- 로그인 여부와 관계없이 광주 데모 좌표를 초기값으로 사용해 추천 쿼리를 즉시 활성화했다.
- 브라우저 위치를 얻으면 실제 좌표로 갱신하고, 실패하거나 5초 내 응답이 없으면 기본 좌표를 유지한다.
- 추천 API가 실패하거나 빈 배열을 반환하면 로컬 기본 추천 카드와 이미지를 표시한다.

### 결과 및 검증

- 비로그인 추천 쿼리 활성화와 API 실패 대체 카드 테스트를 추가했다.
- 관련 테스트 7개, ESLint, 데모 프로덕션 빌드가 모두 통과했다.
